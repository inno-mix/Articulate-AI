# Coding Conventions

> Consistency beats cleverness. When in doubt, copy the pattern of the nearest existing file.

## 1. General

- Small, focused files (aim < 300 lines). One responsibility per module.
- Names say what things are; no abbreviations except well-known ones (`id`, `url`, `llm`, `stt`,
  `tts`, `wpm`).
- No dead code, no commented-out code, no `TODO` without a task id (`TODO(P3.4): …`).
- Constants that are business rules (limits, thresholds) live in `app/domain/limits.py` (backend)
  or come from the API (frontend) — never duplicated magic numbers.
- Comments explain *why*, not *what*.
- Commits: Conventional Commits — `feat(api): …`, `fix(web): …`, `test(api): …`,
  `docs: …`, `chore: …`, `refactor(api): …`. One subtask ≈ one commit.

## 2. Python (apps/api)

### Tooling
- Python 3.12, `uv` for everything (`uv add`, `uv run`). Never `pip install`.
- Ruff (lint + format, line length 100), mypy `--strict` on `app/` (tests: non-strict).
- `pyproject.toml` ruff rules: `E, F, I, B, UP, N, ASYNC, S, SIM, RUF, PT`, ignore `S101` in tests.

### Style
- Type hints everywhere; `from __future__ import annotations` not needed on 3.12.
- Pydantic v2 models for all API I/O and JSONB shapes; `model_config = ConfigDict(extra="forbid")`
  on request models.
- Use `StrEnum` for enums shared between DB and API (`app/domain/enums.py`).
- Async all the way: `AsyncSession`, `httpx.AsyncClient`, async provider SDKs. Never call blocking
  IO in async code; if unavoidable use `await asyncio.to_thread(...)`.
- Dependency injection via FastAPI `Depends` in routers only; services receive plain arguments
  (`db: AsyncSession`, `user_id: UUID`, `llm: LLMService`, …) so they are easy to test.
- Services return domain objects or Pydantic schemas; routers return schemas.
- Raise `AppError` subclasses (in `app/core/errors.py`) for expected failures; never return error
  dicts manually.
- Transactions: the request-scoped session (`get_db`) commits at the end of a successful request
  and rolls back on exception. Services call `await db.flush()` when they need generated ids.
  Streaming endpoints and workers manage their own sessions explicitly (`async with
  session_factory() as db, db.begin():`).
- Never hold a database connection while awaiting an LLM, Deepgram or Azure call, or while
  streaming to a client: in request-scoped services, do the reads/writes you need and
  `await db.commit()` (which returns the connection to the pool) **before** the provider call, then
  write the results afterwards; code that opens its own sessions (streams, voice relay, workers)
  closes them before the call. Never open a session inside another one (the test session factory
  would deadlock and fail after 5 s).
- Logging: `structlog.get_logger(__name__)`; log events as snake_case strings with keyword fields
  (`log.info("report_generated", report_id=..., latency_ms=...)`). Never log transcripts, prompts
  or keys.
- Time: `datetime.now(UTC)`; user-local dates via `zoneinfo.ZoneInfo(profile.timezone)`.

### Module layout rules
```
app/api/v1/<domain>.py        router = APIRouter(prefix="/<domain>", tags=["<domain>"])
app/schemas/<domain>.py       <Thing>Out, <Thing>Create, <Thing>Update
app/models/<domain>.py        class <Thing>(Base)
app/services/<domain>.py      async def <verb>_<thing>(...)
tests/unit/<package>/test_<module>.py
tests/integration/api/test_<domain>.py
```

### Migrations
- One Alembic revision per task that changes the schema, autogenerated then **reviewed by hand**
  (check enums/CHECK constraints, server defaults, index names).
- Never edit a migration that has been committed and applied; add a new one.
- Every migration must `downgrade()` cleanly (tested by `tests/integration/test_zz_migrations.py`:
  upgrade head → downgrade base → upgrade head).

## 3. TypeScript / Next.js (apps/web)

### Tooling
- Next.js 16 (App Router, Turbopack), React 19, TypeScript `strict`, Tailwind CSS v4, shadcn/ui,
  ESLint (Next config), Prettier.
- pnpm workspace; add deps with `pnpm --filter web add <pkg>`.
- Next.js 16 uses `proxy.ts` (not `middleware.ts`) for request interception — Phase 7 only.

### Structure
```
src/app/<route>/page.tsx          thin: layout + feature components
src/features/<feature>/
  components/                     feature UI
  hooks/                          useXxx (TanStack Query wrappers)
  api.ts                          typed calls using lib/api/client
  types.ts                        re-exports of generated schema types used by the feature
src/components/ui/                shadcn primitives (generated; don't hand-edit except theming)
src/components/                   shared app components (AppShell, ScoreBadge, EmptyState…)
src/lib/api/                      client.ts (openapi-fetch), schema.ts (generated), sse.ts, events.ts, errors.ts
src/lib/audio/                    pcm.ts, mic-capture.ts, pcm-player.ts, wav.ts, voice-socket.ts
```

### Style
- Server Components by default; add `"use client"` only for interactive components.
- All API calls go through `src/lib/api/client.ts` (`createClient<paths>({ baseUrl: <API origin
  derived from NEXT_PUBLIC_API_URL>, credentials: "include" })` — generated paths already include
  `/api/v1`). Never hand-write request/response types — import from `schema.ts` (SSE and WebSocket
  payload types live in `events.ts`).
- Data fetching with TanStack Query v5; query keys in `src/features/<feature>/query-keys.ts`.
- Errors: `ApiError` class in `lib/api/errors.ts` (holds `code`, `message`, `status`); UI maps
  `code` to friendly text with a single `errorMessage(code)` helper.
- Forms: react-hook-form + zod; limits mirror the API contract.
- Components: function components, named exports, props typed with `type XProps = {…}`.
- Accessibility: every interactive element reachable by keyboard; labels on inputs; `aria-live`
  regions for streaming text and voice state; colour never the only signal.
- No `any`. No non-null assertions (`!`) except in tests.
- Styling: Tailwind utility classes; design tokens via CSS variables from shadcn theme; no inline
  style objects except for dynamic values (e.g. meter width).

## 4. Tests (both apps)

- Test names describe behaviour: `test_end_session_with_one_turn_marks_abandoned`,
  `it("shows the retry button when the report failed")`.
- Arrange / Act / Assert blocks separated by blank lines.
- No network in unit tests (fakes, `respx` for HTTP). No sleeping — use events/fake clocks.
- Factories for test data in `tests/factories.py` (plain functions, not a library).
- See `testing-strategy.md` for layers and commands.

## 5. Content YAML

- One scenario per file: `content/scenarios/<slug>.yaml`; keys exactly as in
  `data-model.md` (`scenarios`). The loader validates with Pydantic and fails loudly.
- Write persona text in neutral, professional English; avoid real company or person names.
- Pronunciation sets: `content/pronunciation/<slug>.yaml` with `title`, `description`,
  `difficulty`, `position`, `sentences: [{text, focus_words}]`.
